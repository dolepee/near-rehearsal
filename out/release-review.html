What the reviewer can verify

  • The public contract's deployed code hash is pinned to the captured block and the recorded source build.
  • The captured state is imported into local Sandbox; each branch starts from the same state hash.
  • The bad migration is deliberately seeded and its failure is a structured transaction receipt, not a missing read or transport error.
  • The corrected migration completes, and the same user operation advances the counter.
  • The replay is rerunnable from out/public-regression.json; the runtime declaration is checked against the actual run.

Reproduce and inspect

From the repository, with the pinned local Sandbox runtime available:

npm run replay:public then npm run verify:public

The regression manifest declares runtime 2.6.2, protocol 77, commit 2f9ddb711ebd…. The replay records the actual runtime and refuses to report a complete regression if they differ.

Scope and limits

  • Read-only capture: no public write, deployment, upgrade authorization, or production state change was performed.
  • Execution is local NEAR Sandbox, not public testnet or mainnet. Native NEAR state and receipts are the subject; this is not a claim about Tempo custody or an external payment.
  • The bad migration is intentionally seeded for contrast. The packet does not claim a live vulnerability or a general recovery capability.
  • This is one small-state case with one operation. It does not establish adoption, maintainer preference, or release approval.
